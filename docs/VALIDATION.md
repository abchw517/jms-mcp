# JumpServer 3.10.15 实例验收

## 当前验证边界

单元测试使用手工编写的 Swagger 2 合成样本。协议测试使用真实 MCP Python SDK、真实本地 HTTP 监听端口和模拟 JumpServer 上游。没有真实 3.10.15 实例凭证，因此实例验收尚未完成。

2026-10-30 本地验证：Python 3.12.14、MCP SDK 1.30.0，55 项测试通过；Ruff 检查及格式检查通过；源码包与 wheel 构建成功；离线 catalog 正确生成 2 个资产查询工具。协议测试还验证了持有真实有效 SSE 会话 ID 的无认证消息仍被拒绝。

当前执行环境未提供 Docker 引擎，镜像构建交由仓库 CI 验证；Python 3.11/3.12/3.13 测试矩阵也由 CI 执行。上述本地结果不代表真实 JumpServer 实例或全部部署环境已经验收。

## 只读验收

1. 在测试组织创建最小权限账号，获取适合的 Bearer 或私有 Token，填写 `.env`。
2. 使用 `jms-mcp catalog --output catalog.json`。核对工具总数、skipped 原因、路径是否含且仅含一次 `/api/v1`。
3. 在 JumpServer 网页或已验证的 API 客户端中记录一台测试资产 UUID、名称与预期可见数量。
4. 启动服务，通过 `/readyz` 确认初始化完成；分别以 SSE 和 Streamable HTTP 连接。
5. 列出工具。先调用资产列表，传入整数 `limit=1`；核对返回结构和资产可见范围。
6. 验证 search、offset、布尔过滤与数组参数；以实际实例声明的查询参数为准。
7. 传入资产 UUID 调用详情接口，核对请求路径、组织和返回资产。
8. 使用错误 MCP 密钥验证 401；使用失效上游 Token 验证工具错误，区分两层认证。
9. 模拟无权限接口，确认返回 HTTP 403；模拟网络不可达，确认请求受超时限制。
10. 重启网关，验证客户端重连。检查日志不含 Authorization、真实 Token 或完整工具参数。

## 可选写操作验收

只在测试组织执行：精确放行一个创建接口和必要查询接口；传入 `body` 创建一次临时资产，核对审计记录与 API 结果。按实际文档为修改、删除接口单独放行。超时先检查资产与审计，避免重复写入。完成后恢复只读配置。
